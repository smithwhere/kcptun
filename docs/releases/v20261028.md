# KcpTun v20261028 — transport validation and reliability fixes

## Fixes

- Stop and close failed KCP listeners instead of repeatedly logging a latched error in a tight loop.
- Validate FEC shard counts before opening sessions, preventing overflow and division-by-zero crashes. Zero-shard FEC disabling remains supported.
- Validate MTU against encryption and FEC overhead before listening, and check SetMtu failures instead of silently retaining the default.
- Return a nonzero process exit status for command-line and startup errors.
- Encrypt a private buffer in QPPPort.Write so caller-owned plaintext buffers can be reused safely.
- Reject out-of-range connection and QPP counts and invalid keepalive settings at startup.
- Docker builds use vendored dependencies, preserving the smux half-close fix.

## Compatibility

FEC shard counts must be nonnegative. When FEC is enabled, data and parity shard counts must total at most 256. MTU is limited to 1500 bytes and must leave at least 50 bytes after encryption and FEC overhead (minimum 78 with default AES and FEC). Invalid values now fail at startup.

## Downloads and verification

Each platform archive contains client and server binaries. SHA256SUMS contains archive checksums. The release workflow runs race tests, invalid CLI/JSON configuration tests, and loopback half-close regressions on Linux amd64. Other platforms are cross-compiled and packaged without native runtime testing.
